# Задача B — офлайн-читання

Додай постійний кеш останнього успішно завантаженого списку та повного тексту статей.
Через учасника узгодь з агентом редизайну поля стану й підключення статусу в LibraryScreen.tsx.
Збережи поточне оформлення, крім мінімальних змін для відображення стану кешу.

## Критерії приймання

- Після успішного завантаження й перезапуску з вимкненим API доступні всі чотири
  статті та їхній повний текст.
- Якщо запит не вдався, але є кеш, показати збережені дані, банер і час оновлення.
  Текст банера узгодити з макетом; його зміст — немає з’єднання, показано збережене.
- Без кешу показати зрозумілу помилку та дію повторної спроби.
- Після запуску API й оновлення показати актуальні дані та прибрати офлайн-статус.
- Пошкоджений кеш не спричиняє падіння; повторне завантаження залишається доступним.
- Невдалий запит не перезаписує добрий кеш.
- Зберігати весь знімок даних із часом одним ключем/файлом, без частково оновленого стану.
- Не підміняти завантаження вбудованим JSON. Не додавати чергу змін,
  синхронізацію акаунта, service worker чи зовнішній backend.
- Скасування запиту не показувати як втрату мережі.

Для перевірки зупиняти server/serve.py, залишаючи Metro ввімкненим.
Режим польоту симулятора не гарантує вимкнення localhost.
Основні файли: src/services, useLibrary.ts, тести; мінімальне підключення в LibraryScreen.tsx.

Сховище має працювати в React Native на обох платформах, наприклад AsyncStorage,
встановлений через npx expo install. localStorage для iOS/Android не підходить.
Додай версію схеми кешу. Для сценарію без кешу очищати лише ключі Trail Notes,
не весь Expo Go та не дані інших навчальних проєктів.

Перевірити на мобільній платформі учасника й експортувати бандли обох платформ.
Працювати лише у своєму worktree. Локальний коміт створити, merge/push/PR не робити.

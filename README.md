# Trail Notes — практикум з AI-агентами

Потрібно виконати **дві задачі паралельно у двох окремих worktree**, а потім
локально об’єднати результати: редизайн за Figma та підтримку офлайн-читання.

Стартовий застосунок на React Native + Expo має два екрани: бібліотеку
з чотирма матеріалами та сторінку статті. Дані надходять із локального Python API.
Редизайн і постійний кеш потрібно реалізувати самостійно за допомогою агентів.

## 1. Завантажити проєкт

Для цієї інструкції потрібні macOS, Xcode з установленим **iOS Simulator**,
Git, Node.js 22.13.0, npm та Python 3. Застосунок запускаємо через Expo Go,
сумісний з Expo SDK 57: [завантаження Expo Go](https://expo.dev/go).

```sh
git clone https://github.com/Frolov-Danil/trail-notes-agent-workshop.git
cd trail-notes-agent-workshop
npm ci
```

## 2. Запустити локальний сервер

У терміналі з кореня проєкту:

```sh
npm run api
```

Залиш цей термінал відкритим. Він обслуговує API з матеріалами:

```text
Trail Notes API: http://127.0.0.1:8765/articles.json
```

## 3. Запустити застосунок у симуляторі

Відкрий **другий термінал**, перейди до папки проєкту й виконай:

```sh
npm start
```

Коли Metro запуститься, натисни **`i`** в цьому терміналі.
Проєкт відкриється через **Expo Go в iOS Simulator**.
Перевір, що бібліотека показує чотири матеріали й кожен відкриває повний текст.

Тепер працюють два процеси: Python API в першому терміналі та Metro в другому.

## 4. Паралельно виконати дві задачі

Створи дві робочі копії з кореня свіжого клону:

```sh
git worktree add ../trailnotes-redesign
git worktree add ../trailnotes-offline
```

У кожній папці виконай `npm ci` та відкрий окремий чат AI-агента.
Перевір, що кожен агент працює саме у своїй папці.
Git створить локальні гілки автоматично; окремі персональні назви не потрібні.

Перед початком попроси кожного агента запропонувати короткий план і спосіб
перевірки результату. Узгодь між ними поля стану для офлайн-банера,
після чого запускай обидві задачі одночасно.

- Зберегти завантаження матеріалів, відкриття статті та повернення назад.

- Довгі тексти та збільшений системний шрифт мають залишатися читабельними.

### Задача 2 — офлайн-читання

Додай можливість читати **раніше завантажені матеріали**, коли API недоступний.

**Вимоги:**

- Після успішного запиту зберегти на пристрої список усіх матеріалів,
  повний текст статей і час останнього оновлення.
- Якщо API недоступний, показувати збережений список і дозволяти відкривати статті.
- Кеш має працювати **після повного закриття й повторного відкриття проєкту**,
  а не лише поки дані залишаються в пам’яті.
- Показувати офлайн-банер і час останнього оновлення.
- Якщо кешу немає, показувати зрозумілу помилку й кнопку повторної спроби.
- Пошкоджений кеш не повинен спричиняти падіння, невдалий запит — видаляти добрий кеш.
- Після відновлення API й ручного оновлення показувати актуальні дані та прибирати банер.
- Використати постійне сховище React Native. Не підміняти API вбудованим JSON.
- Оформлення виконує інший агент; зміни екрана обмежити підключенням офлайн-стану.

### Як запускати робочі копії

Зупини початковий Metro через **Control + C у другому терміналі**.
API в першому терміналі залиш працювати.

Для редизайну в терміналі з папки `trailnotes-redesign`:

```sh
npx expo start --port 8081
```

Для офлайн-версії в іншому терміналі з папки `trailnotes-offline`:

```sh
npx expo start --port 8082
```

Натискай `i` у потрібному терміналі, щоб відкрити відповідну версію.
Агенти пишуть код паралельно, а перевіряти результати в одному симуляторі можна по черзі.
Обидві копії використовують один API; його зупинка вплине на обидві версії.

## 5. Перевірити офлайн-режим

1. З увімкненим API завантаж матеріали у версії з офлайн-підтримкою.
2. Перейди до **першого термінала, де запущено `npm run api`** і видно рядок
   `Trail Notes API: ...`. Клікни всередині нього й натисни **Control + C**
   (не Command + C). Це зупинить Python API.
3. **Metro залиш працювати.** У застосунку натисни «Обновить».
4. Перевір: список і статті доступні з кешу, видно офлайн-банер і час оновлення.
5. Повністю закрий застосунок у симуляторі, потім знову відкрий цей проєкт
   через Expo Go. Збережені матеріали мають залишитися доступними.
6. У першому терміналі знову виконай `npm run api`, у застосунку — оновлення.
   Дані мають оновитися, офлайн-банер — зникнути.
7. Окремо очисть **лише кеш Trail Notes**, зупини API та перевір помилку без кешу.
   Після запуску API кнопка повторної спроби має відновити завантаження.

Назви «Обновить» і «Повторить» відповідають поточному стартовому інтерфейсу.
Режим польоту не замінює зупинку локального API. Не видаляй Expo Go й дані інших проєктів.

## 6. Об’єднати й показати результат

Перевір кожну задачу окремо та попроси агентів створити локальні коміти.
Потім у чаті агента, відкритому в **основному клоні**, попроси послідовно об’єднати
редизайн і офлайн-підтримку. При конфліктах зберегти обидві поведінки.

В основному клоні після об’єднання:

```sh
npm ci
npm run typecheck
npm test
npx expo start --port 8083
```

Натисни `i` й повтори сценарії онлайн та офлайн вже з новим дизайном.
Готовий результат — **два екрани за Figma та читання збережених статей без API**.
Усі зміни залишаються локально, push і PR не потрібні.
